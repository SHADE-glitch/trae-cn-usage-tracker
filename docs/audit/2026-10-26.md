# tcut — read-only audit report (2026-10-26)

> **A snapshot, not current state.** One-off read-only audit of
> `trae-cn-usage-tracker` at `8672d34`, taken on 2026-10-26: full source reading, probes on copies
> of the live database under `/tmp`, and a full test run. Nothing was installed and no repository
> file was modified during the audit. Repaired items carry **fixed in `<commit>`**; the open ones
> are listed at the end.

- **Baseline**: `python3 -m unittest discover -s scripts/tests` → **261 tests, OK** (53 s). Both
  READMEs and the 15-line per-file count matched the run exactly.
- **Live-database baseline** (read-only copy): 50 sessions, 90 turns, 148 tool calls, 293 prompts.
- **Verdict**: the display conventions (`-` means unknown, `0` means a measured zero) are stated
  everywhere and broken in four places; the incremental cursor is the weak seam — it can hold a
  row forever, skip a fixed parser, or advance past a failed read.

### Why #1 is a P0

The memory documents are on disk and were indexed once: `~/.trae-cn/memory/user_profile.md` and
each project's `project_memory.md`. The table read **0 rows** on this machine, while `sync_state`
held 104 cursors proving the files had been read. Running `tcut sync` again — the remedy the CLI
itself printed — kept it empty, and only `--full` could rebuild it. Three consecutive runs on a
fixture produced 3 → 0 → 0 rows.

## 2. Verified clean

- **Concurrency**: no lock, but one transaction per sync with WAL and `busy_timeout`; four
  concurrent syncs exited 0, `integrity_check` was `ok`, and no table doubled.
- **SQL**: the only dynamic identifiers are table names from literals or `sqlite_master`; every
  value is bound; `LIMIT` values pass through `int()`.
- **Test isolation**: `_hermetic.py` actually refuses a read of the real host directory — the
  probe was blocked until it patched around the guard.
- **Documents**: `UNPARSED_REASONS` matches the format document; `tcut format`'s generated block
  matches `format_doc()`; the eight tab ids match `AGENTS.md`.

## 3. Open after this round

- `last_ts` is still first-write-wins for records that arrive out of order; the fix removed the
  invented day-midnight value, but whether a later measured timestamp should overwrite an earlier
  one is a semantic question for the author.
- A same-size in-place rewrite of a session-memory file is still read as zero new bytes.
- `q_usage_summary.models` folds by model name across providers while the Tokens table splits by
  `(model, provider)`; no provider value exists on this machine to reproduce it.
- DST transitions are untested (this machine has none).
- `_hermetic.py` does not hook `os.stat`, so `Path.exists()` on a real path is not refused.
